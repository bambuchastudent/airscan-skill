# RT-1 Aena VLC airport-wide source feasibility — 2026-10-25

## Candidate and findings

- Owner: **Aena S.M.E., S.A.**; official Valencia airport destination listing: https://www.aena.es/en/valencia/airlines-destinations/airport-destinations.html
- Captured publicly visible facts using a server-side web text renderer on 2026-10-25; page reported **84 destinations / 37 airlines** at inspection. This number is observational evidence, **not** a domain constant, expected fixed size or completeness guarantee. Visible IATA-coded destinations include AMS, BIO, BER, LPA, IBZ, LIS, and many more. Route examples list multiple carriers: AMS (Transavia, easyJet Europe, KLM, Vueling); BIO (Vueling, Volotea, Air Nostrum); BER (Ryanair, easyJet Europe). Aena labels information derived from current airline schedules and subject to change, with no date-by-date departures in this catalog.
- The listing displays airport destinations (IATA identities), country and carrier associations, but some entries do not expose a carrier in the retrieved rendered view. The absence of a visible carrier is **UNKNOWN** rather than proof of no carrier.
- The public crawler's text rendering showed headings/destination entries and carrier links without requiring provided credentials. **It did not expose original HTML bytes, CSS selectors, redirects, response headers, cookie jar, page JS or DOM construction details.** It is therefore *not yet verified* that Java 25 HttpClient + HTML parser can retrieve/parse the complete listing without JS or browser automation. The container network could not resolve www.aena.es (DNS error) and no automatic fetch was performed from it. Source is public HTML, not a documented machine API.
- Robots: direct robots.txt retrieval through available web tooling failed; robots compliance remains **unverified**. No documented API access, rate limit, caching TTL, or guaranteed schema has been found. Design for low-volume conditional GET if permitted, jitter/backoff and no login/CAPTCHA/anti-bot circumvention. Permission and crawling cadence must be reviewed before RT-2.
- Official legal notice: https://www.aena.es/es/aviso-legal.html — section 3 explicitly disclaims complete/exhaustive/current accuracy; section 8 reserves reproduction and exploitation absent written authorization. Section 7 reserves the right to restrict access. **Public readability is not automated-reuse authorization.** Request permission or determine another legitimate access path before building a production ingestion adapter. Page link rules are also restrictive; this document cites source locations for review, not a statement of Aena endorsement.
- Actual destination coverage: source *claims* 84 at inspection; no byte-preserved source payload and therefore **no verified source-entry versus parsed-entry reconciliation**. Seasonal/inactive versus operating flights cannot be inferred. No complete airport route assertion is made.

A count in the page must not be treated as complete authoritative availability or hardcoded in tests.

No remote status, Content-Type header, redirect, cookie, DOM selector or JS dependency was observed using curl. - **Access law:** Aena legal notice https://www.aena.es/es/aviso-legal.html §7 permits discretionary access restrictions; §8 says site content and databases are protected and reproduction/exploitation requires advance written authorization. §3 explicitly disclaims completeness/currency. Neither a successful page view nor robots consent (unverified) grants a reuse/redistribution licence. No written Aena approval is held here. Do not commit actual Aena page markup or run unattended crawlers without an approved path.
- **Result:** no reproducible/authorized acquisition method, source cadence/rights, or parsable original DOM established. **Task 0.3 remains OPEN.** It cannot be accepted based on these page observations.

### Verified documented alternatives, but not yet suitable substitutions

1. **SEGITTUR Dataestur API (strong research lead, not equivalent).** Official service https://www.dataestur.es/apidata/ explicitly describes third-party API use and automated system downloads with generated curl requests. Its published OpenAPI v2 at https://www.dataestur.es/app/themes/mini-mandrake/apidata/openapi.json documents `GET /AENA_DESTINOS_DL`, query parameters `desde (año)`, `desde (mes)`, `hasta (año)`, `hasta (mes)`, `Aeropuerto AENA=Valencia`, historical data since 2004-01, and a 200 XLSX `aena_destinos.xlsx` response. **Observed:** API contract only, not a real XLSX response, response schema, auth/rate policy, Java request or live 2026 airport-wide advertised-route reconciliation. The endpoint's description is *Tráfico aéreo*, i.e. monthly traffic statistics, not a claim that the XLSX lists every current advertised direct route and carrier. General SEGITTUR legal notice https://www.dataestur.es/aviso-legal/ §Propiedad Intelectual restricts redistribution/exploitation without express authorization (specific API license not separately established). Public programmatic retrieval and redistribution are **different legal questions**. Do not republish unlicensed XLSX as a fixture.
2. **Amadeus Airport Routes API (candidate requiring account/data validation).** Developer docs https://github.com/amadeus4dev/developer-guides/blob/master/docs/resources/flights.md describe `GET /v1/airport/direct-destinations?departureAirportCode=VLC` (published example uses MAD) with bearer token and response location `iataCode`. Production availability, allowed caching/reuse, limits, correctness for all VLC airline routes and whether codes denote cities vs airports have **not** been verified. Amadeus FAQ https://admin.developers.amadeus.com/self-service/apis-docs/guides/developer-guides/faq/ warns its Airport Routes data may include closed airports and codes correspond to **destination city IATA codes**, not airport codes. That identity mismatch can violate airport-pair topology as currently defined; needs independent mapping/provenance and architecture review before replacement.
3. **OpenFlights routes.dat (licensed but stale).** https://nginx.openflights.org/data documents ODbL/DbCL use and historic direct-route rows but says route updates ended in **June 2014**. Thus it cannot represent current airport-wide VLC topology in 2026; do not silently promote it as the current catalog. It may only serve as clearly historical example data under its license obligations, not the RT-1 selected source.
4. **Dataestur Amadeus capacity statistics** https://www.dataestur.es/transporte/informacion-transporte-aereo-pasajeros/ explicitly describes a representative **non-exhaustive** sample, mainly inbound Spanish destination metrics, not a complete outgoing VLC advertised route catalog. Inbound capacity != guaranteed reverse advertised origin route.

### Fixture and reconciliation decision

- `worker/src/test/resources/aena/vlc-sanitized-excerpt.txt` remains an explicitly **manually reconstructed** small text excerpt with human-added `Destination:/Carriers:` delimiters; it is **not** a lawful raw Aena HTML fixture or evidence of actual DOM parsing.
- A narrow, offline diagnostic improvement to its helper (`AenaSanitizedExcerptParser.ParseReport`) tracks `sourceRows`, `duplicateDestinationRows`, `rejectedDestinationRows`, and `routes`. Its accounting check is `recognizedCandidateRows == normalizedDistinctRows + duplicateRows + rejectedRows`, *only for the custom excerpt grammar*. A changed/unrecognized row yields omissions and `coverageIsKnown=false`; the result never certifies an Aena snapshot complete.
- This is **not** equivalent to `source candidate destinations = normalized distinct destinations + diagnosed omissions/duplicates` on an actual Aena HTML or licensed source dataset. Such a test needs a genuinely licensed structural fixture, an independently counted source-entry set (including unrecognized entries), and a parser over source-native boundaries. **Task 0.4 remains OPEN.**
- Do **not** copy full Aena pages, restricted datasets, headers containing cookies, or private tokens to git. Retaining no source-native fixture now is intentional compliance, not missing disclosure.

**Recommended default: Option A, permission/export.** Ask Aena for written authorization or an approved documented export/API that explicitly covers airport-wide advertised VLC routes, noncommercial local automated polling, derivative normalization, test fixture excerpt (source-structure preserving), source attribution, caching/update cadence and versioned JSON/CSV/XLSX access. Once rights are documented, capture one minimal genuine fixture on an allowed client, record UTC/status/final URL/redirects/Content-Type/Java 25 fetch/JS-cookie-auth requirements, normalize and reconcile all source candidates. Do not use undocumented endpoints.

**Option B: explicitly approve a source substitution.** Evaluate a current airport-wide feed such as a licensed aviation schedule product or Amadeus route API, first testing identity (airport vs city), allowed redistribution/caching and measured VLC coverage against an independently obtained permitted reference. Replacing Aena or relaxing completeness needs a reviewed OpenSpec/architecture correction **before** calling 0.3/0.4 done.

**Option C: change product semantics.** A historical monthly airport-pair traffic dataset could be used only with an explicit change from "currently advertised direct routes" to "routes with historical traffic"; it is **not** RT-2's approved scope.

**Decision requested:** choose/authorize Option A or approve investigation/contractual access for Option B with explicit coverage criteria, or pause source ingestion. Without this, the correct status is `NEEDS_SOURCE_DECISION`, draft PR #8 unmerged; no RT-2/RT-3.
